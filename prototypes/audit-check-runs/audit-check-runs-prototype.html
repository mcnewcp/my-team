What this one fixture established

          
Durable empirical facts only; architecture remains deliberately undecided.

        

      

      

        

          
Create is not idempotent on the apparent identity tuple

          

            Four POSTs sharing App, head SHA, name, external ID, and check-suite ID returned
            HTTP 201 and four distinct numeric run IDs. The external ID behaved as caller
            metadata, not a uniqueness key.
          

        

        

          
Numeric run ID is the update handle

          

            PATCH returned HTTP 200 and mutated the addressed resource without creating a new
            ID. Changing attempt C from failure to success left its original
            completed_at timestamp intact when no replacement timestamp was sent.
          

        

        

          
The required-check projection followed the newest created run

          

            A newest failure made the PR BLOCKED. A still-newer success made it CLEAN while the
            older failure remained visible through filter=all. GraphQL's PR rollup
            likewise exposed only the newest Audit run for this App/name/SHA.
          

        

        

          
The least-privilege App route worked; the advertised PAT route could not be provisioned

          

            Mutation responses advertised checks=write. The selected-repository
            installation token carried only Checks write and Metadata read, expired after one
            hour, stayed in memory, and was explicitly revoked after the trace.
