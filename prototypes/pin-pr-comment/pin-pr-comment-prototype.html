Can GitHub pin a general comment on a pull request?

Replay the sanitized live evidence from fixture pull request #3. This is platform evidence for the Ledger discussion, not a Ledger design.

The question

Can the issue-comment pin REST endpoint pin a general conversation comment whose subject is a pull request? Test installation tokens carrying Pull requests write alone, Issues write alone, and both together; inspect retry, projection, UI, and cleanup behavior on a real fixture.

The controls below only replay observations actually captured from GitHub. An out-of-order action is rejected instead of inventing behavior that was not tested.

What this one fixture established

          
Empirical platform facts only; the Ledger's supported location remains a later decision.

        

      

      

        

          
A PR conversation comment cannot be pinned by this endpoint

          

            The combined App token carried every tested relevant repository permission, yet
            GitHub returned the subject-specific validation error on the initial call and two
            retries. All three bodies were identical.
          

        

        

          
Isolated grants fail earlier

          

            Pull requests write alone and Issues write alone each returned 403. The combined
            token changed the failure from authorization to validation, but could not make the
            operation supported.
          

        

        

          
Unpin is a silent idempotent no-op here

          

            Two DELETE calls over the never-pinned PR comment both returned 204 with empty
            bodies. A 204 unpin response therefore does not prove that a pin previously existed.
          

        

        

          
Unpinned projections differ

          

            Single-comment GET returned an explicit pin: null. List-comments GET
            omitted the pin member entirely. Neither pinned_at nor
            pinned_by could be observed because GitHub never created a pin.
          

        

        

          
The UI matched the negative API state

          

            Human inspection found no marker, pinned area, or Pin/Unpin menu action on the
            real open pull-request Conversation.
          

        

        

          
Cleanup restored the baseline

          

            Every token was revoked, PR #3 is closed, the disposable branch is deleted, the
            comment is unpinned, and main remains at
            91bdcb713bbb5e60b0db044ca8575a54e8b169fb with no protection,
            rulesets, or open pull requests.
          

        

      

      

        Operational note: a preflight run created fixture PR #2 and stopped before its first
        pin call on a local Bash compatibility error. Its guarded exit closed the PR and
        deleted its branch before the clean PR #3 experiment began.
